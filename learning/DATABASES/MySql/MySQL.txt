DDL Commands used in terms of Tables

a. show tables;
b. CREATE TABLE table_name (attr datatype constraint, attr datatype constraint, ...);
c. DROP TABLE table_name;
d. TRUNCATE TABLE table_name;
e. There are 2 ways to rename a table name:
	1. RENAME TABLE old_table_name TO new_table_name;
	2. ALTER TABLE old_table_name RENAME TO new_table_name;
f. Altering tables can have many operations:
	1. Adding a new column: ALTER TABLE table_name ADD COLUMN column_name datatype constraint;
	2. Adding multiple column: ALTER TABLE table_name ADD COLUMN column_name datatype constraint, ADD COLUMN column_name datatype constraint;
	3. Specify column Position: 
		i. Add first column: ALTER TABLE table_name ADD COLUMN column_name datatype constraint FIRST;
		ii. Add after a specific column: ALTER TABLE table_name ADD COLUMN column_name datatype constraint AFTER existing column_name;
	4. Modify a column or change datatype: ALTER TABLE table_name MODIFY COLUMN column_name datatype;
	5. Adding or removing NOT NULL:
		i. Add NOT NULL: ALTER TABLE table_name MODIFY COLUMN column_name datatype NOT NULL;
		ii. Remove NOT NULL: ALTER TABLE table_name MODIFY COLUMN column_name datatype NULL;
	6. Rename a column: ALTER TABLE table_name RENAME COLUMN old_column_name TO new_column_name;
	7. Rename and change definition together: ALTER TABLE table_name CHANGE COLUMN old_column_name new_column_name datatype;
	8. Drop a column: ALTER TABLE table_name DROP COLUMN column_name;
	9. We can also add or remove constraits using ALTER, and we will see it in constraints 



















DML Commands used with Tables

a. INSERT 
	1. Insert a single row: INSERT INTO table_name VALUES (1, "John", 50000);
	2. Insert multiple rows: INSERT INTO table_name VALUES (2, 'Alice', 55000), (3, 'Bob', 60000), (4, 'David', 70000);
	3. Insert into specific columns: INSERT INTO employee (emp_id, name) VALUES (5, 'Rahul');
	4. Insert data from another table: INSERT INTO target_table SELECT * FROM source_table WHERE condition;
	5. Insert with calculated values: INSERT INTO employee (employee_id, name, salary) VALUES (6, 'Sam', 4000 + 10000);



b. SELECT
	1. Select all columns: SELECT * FROM employee;
	2. Select specific columns: SELECT name, salary FROM employee;
	3. Select unique values: SELECT DISTINCT salary FROM employee;
		Also using COUNT() function with the DISTINCT keyword, we can count the number of unique values.
		SELECT COUNT(DISTINCT salary) FROM employee;
	4. Filter rows: SELECT column1, column2,... FROM table_name WHERE condition;
		Operator used (=, >, <, >=, <=, <> or !=, BETWEEN, LIKE, IN)
		Also AND, OR and NOT operator are used.
	5. Sort data: SELECT column1, column2, ... FROM table_name ORDER BY column1, column2, ... ASC|DESC;
		Order by Several Columns: SELECT * FROM Customers ORDER BY COUNTRY ASC, CustomerName DESC;
	6. Limit Rows: SELECT column_name(s) FROM table_name WHERE condition LIMIT number OFFSET number;
	7. Aggregate functions: MIN(), MAX(), COUNT(), SUM(), AVG()
		SELECT MIN(col_name) FROM table_name WHERE condition;
		To check the number of rows in a table: select count(*) from table_name;
	8. LIKE/NOT LIKE operator (%, _): SELECT column1, column2, ... FROM table_name WHERE column_name LIKE/NOT LIKE pattern;
	9. IN operator: SELECT column_name(s) FROM table_name WHERE column_name IN/NOT IN (value1, value2, ...);
		IN/NOT IN (SELECT): SELECT * FROM Customers WHERE CustomerID IN (SELECT CustomerID FROM Orders);
	10. BETWEEN/NOT BETWEEN operator: SELECT column_name(s) FROM table_name WHERE column_name BETWEEN/NOT BETWEEN value1 AND value2;


c. UPDATE
	1. Update one row: UPDATE table_name SET column = value where condition;
	2. Update multiple columns: UPDATE table_name SET column1 = value1, column2 = value2, ... where condition; 
	3. Update multiple rows: UPDATE employee SET salary + 5000 WHERE salary < 50000;
	4. Update all rows: UPDATE employee SET salary = salary * 1.1;


d. DELETE
	1. Delete one row: DELETE FROM employee WHERE employee_id = 1;
	2. Delete multiple rows: DELETE FROM employee WHERE salary < 3000;
	3. Delete all rows: DELETE FROM employee;

Unique:

	a. Adding a constraint when creating a table:

	CREATE TABLE Persons (
		SR_No int UNIQUE,
    		ID int NOT NULL,
    		LastName varchar(255) NOT NULL,
    		FirstName varchar(255),
    		Age int,
    		UNIQUE (ID)
	);


	b. Naming a Unique Constraint:
	
	CREATE TABLE Persons (
    		ID int NOT NULL,
    		LastName varchar(255) NOT NULL,
    		FirstName varchar(255),
    		Age int,
    		CONSTRAINT UC_Person UNIQUE (ID,LastName)
	);


	c. Adding unique constraint with altering
	
	ALTER TABLE Persons ADD UNIQUE (ID);


	d. Naming a unique constraint with altering
	
	ALTER TABLE Persons ADD CONSTRAINT UC_Person UNIQUE (ID,LastName);


	e. Drop a unique constraint
	
	ALTER TABLE Persons DROP INDEX UC_Person;


2. Primary Key:

	a. Adding PK when creating a table:
	
	CREATE TABLE Persons (
    		ID int PRIMARY KEY,
    		LastName varchar(255) NOT NULL,
    		FirstName varchar(255),
    		Age int
	);


	b. Adding PK for multiple columns

	CREATE TABLE Persons (
    		ID int,
    		LastName varchar(255),
    		FirstName varchar(255),
    		Age int,
    		PRIMARY KEY (ID, LastName)
	);

	Here PK is made up of two columns (ID + LastName)


	c. Naming a PK constraint
	
	
	CREATE TABLE Persons (
    		ID int,
    		LastName varchar(255),
    		FirstName varchar(255),
    		Age int,
    		CONSTRAINT PK_Person PRIMARY KEY (ID, LastName)
	);


	d. Adding PK when altering

	ALTER TABLE Persons ADD PRIMARY KEY (ID);

	
	e. Naming a PK when altering

	ALTER TABLE Persons ADD CONSTRAINT PK_Person PRIMARY KEY (ID, LastName);


	f. Drop a PK

	ALTER TABLE Persons DROP PRIMARY KEY;


3. FOREIGN KEY:

	a. Adding FK when creating a table:
		
	CREATE TABLE Orders (
    		OrderID int PRIMARY KEY,
    		OrderNumber int NOT NULL,
    		PersonID int,
		FOREIGN KEY (PersonID) REFERENCES Persons(PersonID)
	);


	b. Naming a FK constraint:
	
	CREATE TABLE Orders (
    		OrderID int PRIMARY KEY,
    		OrderNumber int NOT NULL,
    		PersonID int,
    		CONSTRAINT fk_Person FOREIGN KEY (PersonID) REFERENCES Persons(PersonID)
	);


	c. Adding FK when altering
	
	ALTER TABLE Orders ADD CONSTRAINT fk_Person FOREIGN KEY (PersonID) REFERENCES Persons(PersonID);


	d. Naming a FK when altering

	ALTER TABLE Orders ADD CONSTRAINT fk_Person FOREIGN KEY (PersonID) REFERENCES Persons(PersonID);

	e. Drop a FK
	
	ALTER TABLE Orders DROP FOREIGN KEY fk_Person;



4. CHECK:

	a. adding check constraint when creating a table

	CREATE TABLE Persons (
    		ID int PRIMARY KEY,
    		LastName varchar(255) NOT NULL,
    		FirstName varchar(255),
    		Age int CHECK (Age >= 18)
	);


	b. Naming a check constraint

	CREATE TABLE Persons (
    		ID int PRIMARY KEY,
    		LastName varchar(255) NOT NULL,
    		FirstName varchar(255),
    		Age int,
    		City varchar(255),
    		CONSTRAINT chk_PersonAge CHECK (Age >= 18 AND City = 'Sandnes')
	);


	c. Adding check when altering

	ALTER TABLE Persons ADD CHECK (Age >= 18);


	d. Naming a check when altering

	ALTER TABLE Persons ADD CONSTRAINT chk_PersonAge CHECK (Age >= 18 AND City = 'Sandnes');


	e. Drop a check constraint

	ALTER TABLE Persons DROP CHECK chk_PersonAge;



5. DEFAULT:

	a. Adding a default value when creating a table:

	CREATE TABLE Persons (
    		ID int PRIMARY KEY,
    		LastName varchar(255) NOT NULL,
    		FirstName varchar(255),
    		Age int,
		Hiredate date DEFAULT CURRENT_DATE(),
    		City varchar(255) DEFAULT 'Sandnes'
	);


	b. Adding a default constraint when altering:

	ALTER TABLE Persons ALTER City SET DEFALUT 'Sandnes';

	
	c. Drop a default constraint:

	ALTER TABLE Persons ALTER City DROP DEFAULT;

JOIN concept:

The INNER JOIN clause returns only rows that have matching values in both tables.

1. INNER JOIN or JOIN: select table1.col1, table1.col2,..., table2.col1, table2.col2,... FROM table1 INNER JOIN / JOIN table2 ON table1.condtion_col = table2.condition_col;




The LEFT JOIN clause returns all rows from the left table (table1), and only the matched rows from the right table (table2). If there is no match in the right table, the result for the columns from the right table will be NULL.

2. LEFT JOIN: select table1.col1, table1.col2,..., table2.col1, table2.col2,... FROM table1 LEFT JOIN table2 ON table1.condtion_col = table2.condition_col;




The RIGHT JOIN clause returns all rows from the right table (table2), and only the matched rows from the left table (table1). If there is no match in the left table, the result for the columns from the left table will be NULL.

3. RIGHT JOIN: select table1.col1, table1.col2,..., table2.col1, table2.col2,... FROM table1 RIGHT JOIN table2 ON table1.condtion_col = table2.condition_col;




The CROSS JOIN clause returns the Cartesian product of two or more tables (combines every row from the first table with every row from the second table).

4. CROSS JOIN: SELECT column_name(s) FROM table1 CROSS JOIN table2;

If you add a WHERE clause (if table1 and table2 has a relationship), the CROSS JOIN will produce the same result as the INNER JOIN clause:

SELECT Customers.CustomerName, Orders.OrderID FROM Customers CROSS JOIN Orders WHERE Customers.CustomerID=Orders.CustomerID;




A self join is a regular join, but the table is joined with itself.

5. Self Join: SELECT column_name(s) FROM table1 T1, table1 T2 WHERE condition;





















UNION and UNION ALL:

The UNION operator is used to combine the result-set of two or more SELECT statements. The UNION operator automatically removes duplicate rows from the result set.

Requirements for UNION: 
-> Every SELECT statement within UNION must have the same number of columns
-> The columns in every SELECT statement must also be in the same order
-> The columns must also have similar data types

UNION Syntax: SELECT column_name(s) FROM table1 UNION SELECT column_name(s) FROM table2;




The UNION ALL operator is same as UNION but it includes all rows from each statement, including any duplicates. 

UNION Syntax: SELECT column_name(s) FROM table1 UNION ALL SELECT column_name(s) FROM table2;















GROUP BY:

The GROUP BY statement is almost always used in conjunction with aggregate functions, like COUNT(), MAX(), MIN(), SUM(), AVG(), to perform calculations on each group.

Syntax: SELECT column1, aggregate_function(column2), column3, ... FROM table_name WHERE condition GROUP BY column1, column3 ORDER BY column_name;





HAVING:

The HAVING clause is used to filter the results of a GROUP BY query based on aggregate functions. Unlike the WHERE clause, which filters individual rows before grouping, the HAVING clause filters groups after the aggregation has been performed.

Syntax: 

SELECT column1, aggregate_function(column2), column3, ... FROM table_name WHERE condition GROUP BY column1, column3 HAVING condition -- The condition on grouped data ORDER BY column_name;













CASE:

CASE
	WHEN condition1, THEN result1
	WHEN condition2, THEN result2
	WHEN conditionN, THEN resultN
	ELSE result
END;


Example:

SELECT ProductName, Price,
CASE
  WHEN Price < 20 THEN 'Low Cost'
  WHEN Price BETWEEN 20 AND 50 THEN 'Medium Cost'
  ELSE 'High Cost'
END AS PriceCategory
FROM Products;

DCL:

a. Grant: The GRANT command gives privileges to a user.
b. Revoke: The REVOKE command removes previously granted privileges.

GRANT/REVOKE privilege_name ON database_name.table_name TO 'username'@'host';

Privilege_name can be SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX



1. Give/remove one permission:

Ex: GRANT/REVOKE SELECT ON company.employee TO 'john'@'localhost';


2. Give/remove multiple permission:

Ex: GRANT/REVOKE SELECT, INSERT, UPDATE ON company.employee TO 'john'@'localhost';


3. Give/remove all permissions on a database:

Ex: GRANT/REVOKE ALL PRIVILEGES ON company.* TO 'john'@'localhost';


4. Give/remove all permissions on all databases:

Ex: GRANT/REVOKE ALL PRIVILEGES ON *.* TO 'admin'@'localhost';



To see the privileges assigned to a user:

SHOW GRANTS FOR 'john'@'localhost';











How to create a user in MySQL:

1. Create one user: CREATE USER 'john'@'localhost' IDENTIFIED BY 'john123';
2. Create multiple users: CREATE USER 'john'@'localhost' IDENTIFIED BY 'john123', 'alice'@'localhost' IDENTIFIED BY 'alice123', 'bob'@'localhost' IDENTIFIED BY 'bob123';


Verify Created Users: SELECT User, Host FROM mysql.user;


1. Remove a user: DROP USER 'john'@'localhost';
2. Remove multiple users: DROP USER 'user1'@'localhost', 'user2'@'localhost', 'user3'@'localhost';


Check the Current Logged-In User: SELECT USER(); OR SELECT CURRENT_USER();


Set a password for user:
ALTER USER 'john'@'localhost' IDENTIFIED BY 'john123';
